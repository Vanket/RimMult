# RimMult — передача проекта (состояние на версии 0.5.0)

Документ для следующего разработчика: что это за проект, что готово и проверено, что
только написано, как устроен код, где грабли и что делать дальше. Подробная архитектура — `docs/DESIGN.md`.

## 1. Что это

**RimMult** — мультиплеер для RimWorld 1.6 (2–10 игроков, только через Steam), без lockstep.

* Репозиторий: https://github.com/Vanket/RimMult (ветка по умолчанию `main`).
* Steam Workshop: https://steamcommunity.com/sharedfiles/filedetails/?id=3813029532
  (`mod/About/PublishedFileId.txt` = `3813029532` — не удалять, иначе загрузка создаст новый предмет).
* Релизы: GitHub Releases — «Latest build» после каждого слияния в `main`, версии — по тегу `vX.Y.Z`
  (мод + выделенный сервер для Linux/Windows).
* Автор/владелец: Vanket. Общается по-русски, тестирует вдвоём с другом (хост + гость), присылает
  `Player.log` или файл кнопки «Отчёт об ошибке» и скриншоты. Изменения принимает через PR/compare
  `main...<ветка>` и сам вливает.

### Два режима

1. **Раздельные колонии** — у каждого своя колония на общей планете, общий мировой календарь и скорость
   (голосование). Каждая игра симулирует только своё. Между играми: посылки (капсулы/караваны), переселение
   пешек, торговля, дипломатия (нейтралитет/союз/война), PvP-рейды (ИИ или «лично»), «помощь союзнику лично»,
   общие разгромленные поселения NPC. NPC-мир у каждого свой.
2. **Кооп на одной карте** — все играют колонию хоста. Симулирует только хост; гость загружает сохранение хоста,
   его копия **никогда не тикает**, хост стримит изменения, приказы гостя выполняются у хоста.

## 3. Сборка и инструменты

* .NET SDK 10 (`global.json`). `dotnet build` собирает всё, `dotnet test` — тесты (xunit, Microsoft.Testing.Platform).
* Мод собирается в `mod/1.6/Assemblies/RimMult.dll` (папка в `.gitignore`); `mod/` — готовая папка мода.
* Проекты:
  * `RimMult.Shared` (netstandard2.0) — протокол, сериализация (`ByteWriter/ByteReader`), пакеты, мир, время,
    кооп-структуры (`Coop/CoopData.cs`), адреса посылок, дипломатия.
  * `RimMult.ServerCore` (netstandard2.0) — `GameServer` (+ `GameServer.Admin.cs` — команды), транспорты.
  * `RimMult.ClientCore` (netstandard2.0) — `ClientSession`, торговля.
  * `RimMult.Net.LiteNet` — UDP-транспорт (LiteNetLib) для выделенного сервера и подключения по адресу.
  * `RimMult.Server` (net10.0) — выделенный сервер (консоль, бэкапы, Docker).
  * `RimMult.Mod` (net472, Harmony, `Krafs.Rimworld.Ref 1.6.4871`) — сам мод.
  * `tests/RimMult.Tests` — тесты протокола/сервера/клиента (без RimWorld).
* `TreatWarningsAsErrors=true`, nullable включён. Неиспользуемое поле = ошибка сборки.
* **В reference-сборках RimWorld нет тел методов** — только сигнатуры. Чтобы узнать члены типа (в т. ч.
  приватные поля/методы), удобно маленьким скриптом на `System.Reflection.MetadataLoadContext` выгрузить их из
  `~/.nuget/packages/krafs.rimworld.ref/1.6.4871/ref/net472/Assembly-CSharp.dll`. Поведение методов — по памяти
  о ванильном коде/декомпиляции; не гадать там, где можно проверить сигнатуру.
* CI: `.github/workflows/build.yml` (сборка+тесты), `release.yml` («Latest build» при слиянии в main),
  `version-release.yml` (релиз по тегу `v*`).
* Мастерская Steam: `tools/workshop/publish.ps1` — сборка, тесты, упаковка и загрузка в предмет 3813029532 через
  запущенный клиент Steam (`-Check` — без загрузки). Подробности — `docs/WORKSHOP.md`.

## 4. Правила кода (как принято в репозитории)

* Комментарии и XML-доки — по-английски, коротко «что и зачем»; документация и интерфейс — по-русски
  (переводы в `mod/Languages/{Russian,English}/Keyed/RimMult.xml`, **оба файла** при каждом новом ключе).
* Сообщения коммитов — по-английски, первая строка — суть, затем список.
* Любое изменение формата пакетов → поднять `ProtocolInfo.Version` (сейчас **26**) и добавить тест на
  кодирование/декодирование. Разные версии протокола не подключаются (понятная ошибка у игрока).
* Harmony: классы патчей применяются **по одному** (`RimMultMod.PatchAll`) — ошибка одного не ломает остальные.
  Для методов, чьи имена параметров не проверены, в патчах использовать позиционные `__0`, `__1`.
  Переопределяемые методы (все `Designator.Designate*`, все `Command.ProcessInput`, `LifeStageWorker`) патчатся
  вручную по всем наследникам (`CoopOverridePatches`).
* Всё работает в главном потоке Unity, раз в кадр через `Multiplayer.Update()` (MonoBehaviour `RimMultRunner`).
* Не сохранять игру посреди тика: действия, требующие сохранения/загрузки, откладываются на следующий кадр
  (пример: `PlayerVisit.Start` → `Update`).

## 5. Как устроено (главное)

### Сеть
Хост в игре поднимает `GameServer` в своём процессе (loopback + Steam P2P + опционально UDP). Выделенный сервер —
тот же `GameServer` без игры. Пакеты — свой бинарный формат (`PacketCodec`). Кооп-трафик — `CoopMessage` с
каналом `CoopChannel`: в режиме коопа сервер пересылает гость→хост и хост→все/один; в режиме раздельных колоний —
только между двумя названными игроками (визиты, `GameServer.HandleVisit`). Позиции — ненадёжный канал, остальное —
надёжный упорядоченный.

### Кооп (папка `src/RimMult.Mod/Coop`)
* `CoopHost` — стрим: позиции 30 Гц (`PositionsFrame`, ≤900 байт, ненадёжно) + пакет состояния каждые 0.1 с
  (`CoopBatch`: исчезнувшее, новые/изменённые вещи как Scribe-XML-фрагменты, патчи `ThingPatch`, выстрелы,
  пометки, зоны, сетки, области, мир `CoopWorld`), сверка `CoopCheck` раз в секунду, смена списка карт
  `MapsChanged`.
* `CoopGuest` — приём: склейка пакетов за кадр, загрузка фрагментов (`ScribeMemory`), замена вещей, отложенная
  замена «занятых» вещей (открыто меню/окно счёта — `Busy`), позиции, сверка, перезагрузка игры при новой карте.
  `Applying=true`, пока применяется поток — патчи-перехватчики в это время не срабатывают. `CopyInPlay` — копия на
  экране (не тикать, не сохранять).
* `ScribeMemory` — сохранение/загрузка одного объекта через Scribe в памяти. Ссылки разрешаются по кешу
  «load ID → объект» (`Referenceables`): регистрируются только ID, встречающиеся во фрагменте. `replacedIds`
  исключает старые объекты, которые фрагмент заменяет. Трупы и караваны сохраняются с пешками внутри (у хоста
  эти пешки — мировые, у гостя их нет). Ссылки на битвы/боевой лог вырезаются.
* `CoopCommands` — приказы гостя, описанные так, чтобы хост нашёл то же самое у себя: дезигнатор, пункт меню по
  тексту, гизмо по типу+надписи, приоритеты, исследование, Shift (флаг `Queue`), квесты, команды модов. Гизмо,
  открывшее окно или прицел у хоста, отправляется гостю назад (`RunLocally`) и выполняется в его копии.
* `CoopTargeting` — прицельные команды: гость целится у себя, выбранная цель уходит хосту; хост жмёт ту же кнопку
  и сразу завершает прицеливание (сохраняя/восстанавливая состояние своего `Targeter`).
* `CoopEdits` — настройки, которые гость меняет в копии (счета, склады, растения, владельцы, зоны, настройки
  пешек, политики, области): сравнение с последним состоянием от хоста, изменения уходят хосту целиком.
* `CoopWorldSync` — NPC-мир коопа: отношения, исследования, письма, политики, квесты, данные модов (`ModSync`),
  глобус (`CoopGlobe`: караваны, объекты мира, приказы каравану, формирование каравана).
* `CoopVisuals` — плавное движение, летящие снаряды, прицелы, прогресс-бары у гостя.

### Раздельные колонии (папка `src/RimMult.Mod/Sync`)
* `WorldSync` (вход/выход из мира, календарь, отчёт о колониях), `TimeSync` (скорость), `RemoteColonies`
  (колонии других игроков на глобусе, меню каравана/капсул), `Parcels` + `ThingPackage` (посылки, адреса —
  `Shared/World/ParcelAddress.cs`), `PawnTransfer`, `SharedSettlements`, `DiplomacyUi`.
* `PlayerRaids` — рейды: отряд уходит посылкой `raid:`, у защитника его ведёт ИИ (`LordJob_AssaultColony`) под
  скрытой враждебной фракцией; выжившие возвращаются `raidret:` караваном.
* `PlayerVisits` — **визиты** (рейд лично и помощь союзнику): игрок сохраняет свою игру (`RimMult_VisitHome`),
  выходит из мира и загружает игру другого игрока как гость (кооп-механика между двумя игроками). Командует
  только своими пешками: их приказы уходят как сериализованные `Job` (`CoopCommandKind.Job`), у хозяина —
  белый список работ для рейдеров, всё — для помощников; между приказами `Wait_Combat`. В копии рейда стороны
  меняются местами (рейдеры → `Faction.OfPlayer`, колония защитника → враг). Конец визита → своя игра
  загружается обратно, пешки возвращаются посылкой.
* **Просмотр колонии союзника** — тот же визит без пешек: `JoinRequest` с байтом `PlayerVisits.WatchVisit`, хозяин
  пускает союзника, если включена галочка `AllowWatch`; в копии ничего не меняет стороны, кнопки и приказы не
  работают, «Вернуться домой» — под строкой статуса. Союз разорван → визит заканчивается. Отказ — сразу, без повторов.

### Сервер
`GameServer`: рукопожатие (протокол, пароль, баны, лимит, версия игры, хэш модов), список игроков, мир
(`WorldState` формат 9: определение планеты, колонии, время, почта, отношения, разгромленные поселения, летопись и
статистика игроков, поселения NPC, договоры, рынок, цены мира), координатор времени, дипломатия, пересылка кооп-трафика, команды
(`/help` в чате).

### Дипломатия, договоры, репутация
* Правила — `DiplomacyBook` (`Shared/World/Diplomacy.cs`). Войну объявляет один, всё остальное — по согласию.
  **Договоры** (`Treaty`: пакт, перемирие, дань) хранятся в `WorldState.Treaties` и уходят клиентам в `WorldUpdate`;
  пока договор действует, войну объявить нельзя — только разорвать договор (`BreakTreaty`, видно всем). Мир всегда
  даёт перемирие на `TruceDays` (5 дней), мир с данью — договор о дани. Ультиматум (`DemandTribute`): согласие — дань,
  отказ — война (только при PvP). Условия (`TreatyTerms`: дни, серебро, кто платит) едут в `DiplomacyRequest` и
  `DiplomacyNotice`.
* **Дань** (`GameServer.Treaties.cs`): раз в квартал (15 дней мира) сервер шлёт плательщику `TributeDue`; игра
  спрашивает «Заплатить / Позже / Отказаться» (`Sync/Tribute.cs`), серебро уходит посылкой `tribute:<id>|<сумма>`,
  сервер засчитывает платёж (`DiplomacyBook.Paid`). Отказ = разрыв договора. Истёкший договор — «соблюдён» обоими.
* **Репутация** — поля `PlayerStats` (объявил войн, нарушил/соблюл договоров, уплатил дани): колонки в летописи,
  строка на колонии игрока (`UI/Reputation.cs`).
* **Исследования союзнику** (`Sync/ResearchShare.cs`): пустая посылка `research:<def>|<очки>`, половина стоимости
  изученного проекта, каждый проект каждому союзнику один раз (`RimMultGameComp.SharedResearch`); сервер пропускает
  только между союзниками.
* **Выкуп пленных**: во время войны кнопка обмена на колонии врага — «Выкуп пленных», в обмене только серебро и
  пленные (`PawnTransfer.CanSend(…, prisoners: true)`), пленные приходят свободными.
* **Чат**: `ChatMessage.Scope` (все / союзники / шёпот), разбор `/a`, `/w`, `/r`, `/all` (и русская раскладка) —
  `ClientCore/ChatInput.cs`.

### Торговля: витрина и рынок
* **Витрина** в окне обмена: каждая сторона шлёт `TradeMessageKind.Catalog` (всё, что могла бы отдать, ключ — индекс
  строки), партнёр — `Request` (ключ → сколько). Просьбы ничего не меняют в предложении и версиях: владелец видит их
  в своём списке и жмёт «Дать, что просит». Принятие и коммит — как раньше.
* **Рынок** (`GameServer.Market.cs`, `Shared/World/Market.cs`, окно `UI/Window_Market.cs`, кнопка «Рынок» в окне
  мультиплеера, только раздельные колонии). Сервер держит обе стороны сделки: товары лота и серебро награды заказа
  лежат в `WorldState` (`MarketLots`/`MarketOrders`, с `Payload`), клиентам уходит список без товаров
  (`MarketState`). Покупка — серебро покупателя приходит в `MarketAction.BuyLot`, сервер раздаёт посылки
  `market:<вид>` (`ParcelAddress.MarketKind`) обоим; опоздал или цена другая — серебро назад. Заказ: награда уходит
  при размещении, выполнивший шлёт товары (`FulfillOrder`), просроченный заказ возвращает награду. С врагом сделок нет.
  Товары берутся со складов дома (`Sync/Goods.cs`).
* **NPC на рынке.** Сервер не знает вещей RimWorld, поэтому за фракции играет одна игра — **маклер**
  (`MarketState.BrokerPlayerId`: хост, если он в мире, иначе тот, кто в мире дольше всех; `GameServer.BrokerId`).
  `Sync/MarketBroker.cs` раз в полдня игры: лот из обычного ассортимента фракции (`TraderKindDef.stockGenerators`,
  цена ×1,1–1,4 к рыночной), заказ повседневного товара (награда ×1,2–1,6), выполнение заказа игрока, который висит
  2+ дня (если награда ≥ 110 % цены), покупка лота игрока дешевле 85 % цены. Действия `MarketActionKind.Npc*` сервер
  принимает только от маклера. Фракция в сделке — `def + номер` (как в `NpcLayoutSync`), ключ владельца —
  `NpcTrader.OwnerKey` (верхний бит, никогда не SteamID); почта «для NPC» не хранится. Адрес посылки несёт фракцию
  (`market:<вид>|<def>|<номер>`) — игра получателя прибавляет доброжелательность. NPC-лоты истекают
  (`MarketLot.ExpiresTick`), NPC-заказы — по сроку.
* **Цены мира** (`Shared/World/MarketPrices.cs`, в `WorldState`): множитель на предмет (по defName) — покупки у NPC
  поднимают (до ×2), продажи NPC снижают (до ×0,5), каждый день 8 % пути назад к 1. Раз в 5–9 дней новость: категория
  (`ThingCategoryDef`) дорожает ×1,2–1,5 или дешевеет ×0,65–0,85 на 7–15 дней (запись в летописи). Игра считает цену
  своей вещи сама (`WorldPrices.FactorOf`: множитель предмета × новости его категорий и их родителей).
* **Комиссия**: `Market.FreeListings` (3) лотов и заказов бесплатно, за каждый следующий `FeePercent` (5 %) цены —
  серебро сжигает игра игрока, сервер проверяет сумму `MarketAction.Fee`.

### Летопись мира и курсоры в коопе
* **Летопись** (`GameServer.Chronicle.cs`, `Shared/World/Chronicle.cs`, окно `UI/Window_Chronicle.cs`, кнопка
  «Летопись мира» в окне мультиплеера). Сервер сам записывает то, что видит: создание мира, первый вход игрока,
  основание/оставление колоний (по разнице списков `MyColonies`), войну/мир/союзы, рейды (`raid:` → начало,
  `raidret:` → итог, мёртвые — строки `D:` в сводке), помощь, посылки, разгромленные поселения. Богатство и колонисты
  — отчёт игры раз в 30 с (`ColonyStatsReport`, сервер отсекает повторы). Всё хранится в `WorldState`, поэтому
  работает и с хостом через Steam (мир хоста лежит в его сейве), и на выделенном сервере. Не больше 1000 записей.
  Тексты — по ключам `RimMult.Chronicle.<Kind>` на языке читателя.
* **Курсоры** (`Coop/CoopCursors.cs`, канал `CoopChannel.Cursors`, ненадёжно, до 15 Гц): гость шлёт свой курсор и
  выделение хосту, хост — всё вместе гостям. Рисуются цветом игрока: крестик с именем
  (`MapInterfaceOnGUI_BeforeMainTabs`, под окнами) и рамки вокруг выделенного (`Map.MapUpdate`). Галочка в
  настройках мода. В визитах (рейд/помощь лично) не работают.

## 7. Чек-лист проверки в игре

* **Кооп, гость:** Shift-очередь; атака по цели и способность (в т. ч. псикаст Vanilla Psycasts Expanded);
  счёт на верстаке (добавить/изменить/удалить, окно счёта открыто, пока хост работает); склад; выбор растения;
  владелец кровати; расписание и политика пешки; разрешённая область; труп убитого животного (виден, с крестиком
  «запрещено»); караван: сформировать, отправить, пункт меню глобуса; хост входит на точку квеста — у гостя
  перезагрузка и новая карта; принять квест у гостя; кнопка «Загрузить заново».
* **Раздельные колонии:** война → «Отправить рейд (ведёт ИИ)» и «Напасть лично»: загрузка, управление бойцами,
  «Отступить», «Похитить», «Украсть», «Вернуться домой», конец рейда → возврат домой и караван выживших; защитник
  не видит приказов. Союз → «Помочь лично»: помощники приходят туда, где союзник; союзник не может ими
  командовать; «Вернуться домой» → люди возвращаются капсулами.
* **Моды как у хоста:** у друга другой порядок / лишний / старый мод (или старый RimMult) → «Моды» рядом с хостом в
  списке друзей (без входа) → экран различий со сборками RimMult → «Сделать всё как у хоста» → подтверждение →
  окно загрузки из Мастерской → перезапуск с модами в порядке хоста → сам подключается. Клиентские моды остались.
* **Сервер:** `/players`, `/kick`, `/ban` из чата хоста; `docker compose up -d` и `docker attach rimmult`;
  бэкапы в `server-data/backups`.
* **Курсоры (кооп):** крестик и имя друга в его цвете там, куда он навёл мышь; рамка вокруг того, что он выделил;
  у хоста видны гости, у гостей — хост и другие гости; галочка в настройках выключает.
* **Договоры:** «Дипломатия» на колонии друга → пакт на 10 дней (у обоих письмо, «Объявить войну» серая) →
  ультиматум «дань или война» → согласие → окно «Пора платить дань» → «Заплатить» (серебро ушло, у друга письмо
  «Дань от …», в летописи «уплатил дань») → «Разорвать договор» (у друга письмо, в летописи и в колонке «Нарушил
  договоров»). Война → «Мир, заплатив дань» → дань идёт, перемирие в инспекторе колонии.
* **Чат:** кнопка «Все/Союз» у поля ввода; `/a`, `/w Имя текст`, `/r текст` — строки видят только те, кому они.
* **Исследования и выкуп:** союзник → «Дипломатия» → «Поделиться исследованием» → у друга письмо и прогресс
  проекта; война → «Выкуп пленных» → в обмене только серебро и пленные, пленный приходит колонистом.
* **Админ-панель** (`UI/Window_Admin.cs`, `GameServer.AdminPanel.cs`, пакет `AdminAction`): кнопка в окне мультиплеера
  у хоста и назначенных `/admin` (`PlayerInfo.IsAdmin` ставит сервер). Предметы (любой предмет, материал, качество,
  количество — делает игра админа, `ThingPackage`) и серебро уходят посылкой `admin:gift`, исследования — `admin:research`
  (defName по строкам, у получателя `FinishProject`), любому игроку мира, в том числе не в сети. Отношения между двумя
  игроками ставятся принудительно (`DiplomacyBook.Force`, договоры кончаются), договоры рвутся (`EndTreaties`), лоты и
  заказы убираются (товар/награда — владельцу), цены сбрасываются, новость рынка — сразу, пауза для всех — удержание
  времени `AdminPauseHold`. Сервер проверяет права (`IsAdmin`), посылки с адресом `admin:` от игроков отбрасывает.
  В летопись не пишется (так решил Vanket).
* **Админ-панель:** хост → «Админ-панель» → игрок → «Предметы…» (поиск, материал, качество, сколько) → у игрока письмо
  «Подарок от …»; «Исследования…» → «Всё до уровня: Индустриальный» → «Завершить» → проекты изучены; отношения «Война»
  между двумя игроками; «Пауза для всех» / «Снять паузу». Не-админ кнопки не видит; `/admin Имя` — видит.
* **Ракеты (InterRim Ballistic Missile)** — `Sync/MissileStrikes.cs`, через отражение (мод не обязателен). Префикс
  `WorldObject_Missile.OnArrived`: наша ракета прилетела на клетку `RemoteColony` → посылка `missile:<body>|<warhead>|<откуда>`
  без вещей, ракета исчезает. Сервер пропускает её как рейд (`RaidRefusal`: PvP, война, защитник в мире), иначе она
  возвращается отправителю («ушла в пустоту»); летопись `MissileStrike`. У защитника — `AIFactionMissileUtility.LaunchMissile`
  от скрытой враждебной фракции (`PlayerRaids.RaidFaction`) с клетки нападавшего на свою карту, клетка — `SelectImpactCell`:
  ракету видно, её сбивает ПВО мода, удар — как у NPC. Наведение: тактической ракете мод требует карту — префикс
  `ChoseTacticalWorldTarget` ставит цель на клетку колонии без клетки карты; обе цели (тактика и стратегия) по чужой
  колонии проверяются `PlayerRaids.CanAttack`. Методы пусковых (`TargetNext` и др.) реализованы явно — вызываются через
  интерфейс `IIRBMLauncher`.
* **Орбитальный удар (Royalty)** — `Sync/OrbitalStrikes.cs`: кнопка «Орбитальный удар» на колонии врага (война, PvP, он в
  мире) со списком колонистов с разрешениями `RoyalTitlePermitWorker_OrbitalStrike` (бесплатно после перезарядки, иначе
  за благосклонность — как в игре); посылка `orbital:<permit>` по правилам рейда, летопись `OrbitalStrike`. У защитника —
  `Bombardment` с параметрами `royalAid` у его колонистов (не под толстой крышей).
* **Шаттлы** (`Sync/Shuttles.cs`): шаттл в перелёте лежит в том же контейнере, что и груз (`ActiveTransporterInfo.SetShuttle`),
  — посылка/рейд/помощь отдали бы его как вещь. В трёх действиях прибытия к игроку шаттл вынимается (`RemoveShuttle`) и
  садится дома (`GetBestShuttleLandingSpot`).
* **Помощь караваном с техникой**: в помощь уходит экипаж (`VehicleCompat.Crew`), техника ждёт у колонии союзника;
  `DeliverHelpReturn` сажает вернувшихся в ждущий караван (по клеткам колоний союзника).
* **Кик и бан:** хост, окно мультиплеера → «⋮» справа от игрока → «Кикнуть» / «Забанить» (то же, что `/kick #id`,
  `/ban #id`); забаненный не заходит, «/unban SteamID» снимает.
* **Рейд на технике (Vehicle Framework):** у каравана с машинами два вида рейда. «Рейд на технике»: в посылку идут
  члены каравана (`caravan.pawns` — машины с пассажирами внутри, их обработчики сохраняются вместе с машиной), у
  защитника машины появляются у края карты (`CellFinderExtended.RandomClosewalkCellNear` VF) и входят в тот же
  `LordJob_AssaultColony` — VF сам ведёт технику, как у NPC-рейдеров; машина считается в бою, пока в ней есть живой
  экипаж; отступившие машины ловит тот же перехват `Pawn.ExitMap`, домой они приходят караваном (VF делает из него
  `VehicleCaravan`). В «лично» техникой правит ИИ, визитёр командует пешими. «… — только экипаж»: люди выходят из
  машин и атакуют, машины ждут у колонии, выжившие садятся обратно. Совместимость — `Sync/VehicleCompat.cs` (через
  отражение, без ссылки на сборку VF); в посылки, переселение и помощь техника не идёт (`PawnTransfer.CanSend`).
* **Кнопка «Вернуться домой» при просмотре** и клик по строке статуса обрабатываются **до** интерфейса игры
  (префикс `UIRoot_Play.UIRootOnGUI`): нарисованные поверх всего, они не получали клик — его забирало выделение на карте.
* **Просмотр:** союзник → «Посмотреть колонию» → подтверждение → загрузка его игры → видно его пешек и работу,
  приказы и кнопки не работают («Вы только смотрите») → «Вернуться домой» вверху → своя колония. У союзника
  сообщения «смотрит» / «больше не смотрит»; с выключенной галочкой — сразу отказ.
* **NPC на рынке:** через полдня игры после входа на рынке появляются лоты «(фракция)» и заказы фракций; купить лот
  → товар капсулой и «Отношения с …: +N»; заказ игрока, висящий 2+ дня с хорошей наградой, выполняет фракция; лот
  дешевле 85 % цены покупает фракция. Вкладка «Цены и новости»: после сделок с NPC цены сдвигаются, раз в 5–9 дней
  новость (сообщение «Летопись: Новости рынка…»). Четвёртый лот — комиссия 5 %.
* **Витрина и рынок:** в обмене справа внизу склад друга, «+» → у друга подсветка и «Дать, что просит»; «Рынок» →
  выставить лот → друг покупает, пока вы в лобби → при входе в мир письмо «Лот продан» с серебром; заказ «10
  медицины, 400 серебра» → друг «Выполнить» → у вас «Заказ привезли», у него «Награда за заказ».
* **Летопись:** кнопка «Летопись мира» в окне мультиплеера; события (основание колонии, война, рейд и его итог,
  посылка) появляются у всех; вкладка «Игроки» — богатство и колонисты через ~30 с после входа в мир; после
  перезапуска хоста (через Steam, из того же сейва) летопись на месте.
* При ошибках — «Отчёт об ошибке» в окне мультиплеера (файл с версиями, модами и логом).

## 8. Грабли, на которые уже наступали
* **«Не могу отправить караван» (Vehicle Framework).** В 1.6 караван из дома нельзя отправить без маршрута, игра сама
  открывает выбор маршрута при открытии окна — а VF это убирает (транспайлер `PostOpen`). «Отправить» тогда только
  пишет «Сначала нужно построить маршрут путешествия». `Patches/CaravanRoutePatch.cs`: если отправка не вышла только
  из-за маршрута (ванильная `CheckForErrors` и VF `CaravanFormation.TrySendVehicleCaravan`), сразу открывается
  планировщик маршрута. Вкладки окна при этом могут «множиться» (VF чистит их в `PostClose` только когда не выбирают
  маршрут) — это VF, на отправку не влияет.
* **Не получалось назвать поселение** (только на паузе). Время за окнами идёт (`WindowsForcePausePatch`), а игра раз в
  1000 тиков (`Faction.FactionTick`) снова открывает окно названия, и новое заменяет открытое — введённое стиралось
  каждые пару секунд. `NamingDialogOncePatch` (префикс `WindowStack.Add`): пока открыто окно `Dialog_GiveName`, второе не
  открывается. (`WindowStack.IsOpen<T>` сравнивает тип точно — для базового класса не годится.)
* **Свернул игру — у всех стоп.** «Работать в фоне» (`Prefs.RunInBackground`) по умолчанию выключено, и свёрнутая
  игра встаёт целиком: колония не считается, сеть не обслуживается, остальные упираются в горизонт общего времени.
  `Multiplayer.KeepRunningInBackground`: пока есть сессия (или свой сервер), `Application.runInBackground = true`;
  после — снова как в настройках.
* **Маршрут на глобусе не строился вообще** (и ванильная кнопка, и кнопка машин VF). Планировщики при старте
  ставят паузу (`TickManager.Pause`) и сами закрываются, как только игра не на паузе (`ShouldStop`), а `TimeSync`
  каждый кадр возвращает общую скорость — планировщик закрывался сразу. `Patches/RoutePlannerPatches.cs`: в
  мультиплеере планировщик (ванильный `WorldRoutePlanner` и VF `VehicleRoutePlanner`) не ставит паузу (скорость
  возвращается сразу после `Start`, чтобы это не стало голосом за паузу у всех) и не закрывается из-за идущего
  времени: мир идёт, пока игрок выбирает путь.

* **ID в раздельных колониях не совпадают**: `Thing_Human512` у двух игроков — разные пешки. Поэтому чужую карту
  нельзя «подгрузить» в свою игру; визиты загружают чужую игру целиком.
* **Гость коопа не тикает**: всё, что в ванили считается в тике (оверлеи, сети, ИИ), у гостя не обновляется само —
  только из потока хоста.
* **Мёртвые пешки, пешки караванов** у хоста — мировые пешки; труп/караван ссылается на них по ID → у гостя
  ссылки не разрешались (труп «в сломанном состоянии» удалялся). Решено сохранением пешек внутрь.
* **Открытые меню/окна держат старый объект**: замена вещи под открытым меню ломала интерфейс → `Busy` и
  отложенная замена.
* **Steamworks на выходе из игры** бросает `InvalidOperationException` → обёрнуто.
* **Settlement.def.texture == null в 1.6** → цвета игроков: красить исходный материал, в try/catch.
* **Тайлы в 1.6 — `PlanetTile`** (слои), в протоколе передаются строкой (`ToString`/`TryParse`).
* **Краш при запуске с большой сборкой (0.5.0):** патчи на всех наследников (`Designator.Designate*`,
  `Command.ProcessInput`, `Verb.OrderForceTarget`, `JobDriver.GetReport`) ставились в конструкторе мода — Harmony
  компилирует целевые методы, это запускает статические конструкторы классов других модов, а они грузят текстуры
  не из главного потока → «Graphics device is null», краш. Теперь такие патчи помечены `[LatePatch]` и ставятся
  в `LatePatches` (`[StaticConstructorOnStartup]`, главный поток, после загрузки). Новые патчи «по всем
  наследникам» — только так. Проверено в игре на ~300 модах: краша нет.
* **Статические поля с текстурами/материалами** (`Texture2D`, `Material`) — игра при загрузке пишет «probably needs
  a StaticConstructorOnStartup attribute». Классу с таким полем ставить `[StaticConstructorOnStartup]` (сами поля
  у нас ленивые, `??=`, грузятся в главном потоке).
* **Клавиша чата** — `\` (Backslash). Y занята ванильной `Misc3` (третья кнопка у выделенного): конфликт в логе
  и двойное срабатывание. Новые клавиши проверять по `Data/*/Defs/Misc/KeyBindings` и модам владельца.
* **Микростопы ночью на скорости 3 (2026-10-04).** RimWorld сам удваивает скорость 3 (×12, 720 тиков/с), когда
  «ничего не происходит» (`TickManager.NothingHappeningInGame`: все спят, угроз нет). У хоста все спали — 720, у друга
  нет — 360: быстрая колония упиралась в горизонт и вставала раз в секунду. Теперь каждая игра сообщает `Idle` в
  `AuthorityReport`, сервер даёт `Boost` в `TickGrant` только если тихо у всех (`TimeCoordinator.ResolveBoost`, допуск и
  планка «узкого места» удваиваются), а патч на `TickRateMultiplier` держит ×6 без `Boost`. И вместо стопа на горизонте
  игра плавно сбавляет темп, когда до него осталось меньше 60 % допуска (`TimeSync.SpeedFactor`).
* **Поселения NPC у игроков стояли по-разному (2026-10-04)** при одинаковой планете: их расстановка зависит и от
  настроек модов, а их RimMult не сравнивает. Теперь создатель мира (у хоста через Steam — хост) отдаёт серверу свою
  расстановку (`NpcLayout`, `WorldState` формат 6), и каждая игра при входе в мир приводит свои поселения NPC к ней:
  те же клетки, фракции (def + какая по счёту из этого def), названия; разгромленные не возвращаются, клетки с
  колониями не трогаются. Для старых миров хост отдаёт расстановку при первом входе.
* **У игроков была разная планета (2026-10-08):** сетка клеток та же, а реки, дороги, рельеф и карта клетки разные
  (у хоста мир сгенерирован давно, друг сгенерировал его сегодня со своими модами). Генерация из сида одинакова только
  при одинаковых модах на момент генерации, а это не проверить. Теперь хост (на выделенном сервере — создатель мира)
  при входе отдаёт серверу планету (`WorldTerrain`, `WorldState` формат 10, протокол 27): массивы клеток слоя
  поверхности ровно так, как их пишет сейв (`SurfaceLayer.TilesToRawData`: биом, высота, рельеф, температура,
  осадки, болота, загрязнение, реки, дороги, мутаторы), плюс названия гор/морей и достопримечательности; def'ы
  переводятся по имени. Остальные при входе сравнивают отпечаток (`RimMultGameComp.TerrainHash`) и, если он другой,
  скачивают и перенимают (`RawDataToTiles` на свежих клетках, пересчёт путей и отрисовки). Новая колония перенимает
  планету до выбора места. Клетки под своими картами игра не трогает (кроме рек и дорог). В сейв хоста планета не
  пишется: при следующем запуске хост отдаёт её снова.
* **Разрыв Steam-соединения при генерации планеты/карты (2026-10-04, ~300 модов):** игра замирает на минуты, наша
  сеть живёт в главном потоке → другая сторона 120 с ничего не слышит и отключает (друг создавал колонию — сервер хоста
  написал `left`). Теперь `Steam/SteamKeepAlive.cs`: если главный поток молчит > 2 с, фоновый поток раз в секунду шлёт
  heartbeat всем Steam-пирам (только отправка; читает и решает по-прежнему главный поток). UDP (LiteNetLib) держит
  соединение сам. Колония, созданная без связи, к миру не привязывается — в лобби кнопка «Подключить этот сейв».
* **Мод Multiplayer (Zetrith)** несовместим (`incompatibleWith` в `About.xml` + предупреждение при запуске).
