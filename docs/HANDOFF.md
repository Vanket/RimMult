# RimMult — передача проекта (состояние на версии 0.5.0)

Документ для следующего разработчика: что это за проект, что готово и проверено, что
только написано, как устроен код, где грабли и что делать дальше. Подробная архитектура — `docs/DESIGN.md`.

## 1. Что это

**RimMult** — мультиплеер для RimWorld 1.6 (2–10 игроков, только через Steam), без lockstep.

* Репозиторий: https://github.com/Vanket/RimMult (ветка по умолчанию `main`).
* Steam Workshop: https://steamcommunity.com/sharedfiles/filedetails/?id=3813029532
  (`mod/About/PublishedFileId.txt` = `3813029532` — не удалять, иначе загрузка создаст новый предмет).
* Релизы: GitHub Releases — «Latest build» после каждого слияния в `main`, версии — по тегу `vX.Y.Z`
  (мод + выделенный сервер для Linux/Windows).
* Автор/владелец: Vanket. Общается по-русски, тестирует вдвоём с другом (хост + гость), присылает
  `Player.log` или файл кнопки «Отчёт об ошибке» и скриншоты. Изменения принимает через PR/compare
  `main...<ветка>` и сам вливает.

### Два режима

1. **Раздельные колонии** — у каждого своя колония на общей планете, общий мировой календарь и скорость
   (голосование). Каждая игра симулирует только своё. Между играми: посылки (капсулы/караваны), переселение
   пешек, торговля, дипломатия (нейтралитет/союз/война), PvP-рейды (ИИ или «лично»), «помощь союзнику лично»,
   общие разгромленные поселения NPC. NPC-мир у каждого свой.
2. **Кооп на одной карте** — все играют колонию хоста. Симулирует только хост; гость загружает сохранение хоста,
   его копия **никогда не тикает**, хост стримит изменения, приказы гостя выполняются у хоста.

## 3. Сборка и инструменты

* .NET SDK 10 (`global.json`). `dotnet build` собирает всё, `dotnet test` — тесты (xunit, Microsoft.Testing.Platform).
* Мод собирается в `mod/1.6/Assemblies/RimMult.dll` (папка в `.gitignore`); `mod/` — готовая папка мода.
* Проекты:
  * `RimMult.Shared` (netstandard2.0) — протокол, сериализация (`ByteWriter/ByteReader`), пакеты, мир, время,
    кооп-структуры (`Coop/CoopData.cs`), адреса посылок, дипломатия.
  * `RimMult.ServerCore` (netstandard2.0) — `GameServer` (+ `GameServer.Admin.cs` — команды), транспорты.
  * `RimMult.ClientCore` (netstandard2.0) — `ClientSession`, торговля.
  * `RimMult.Net.LiteNet` — UDP-транспорт (LiteNetLib) для выделенного сервера и подключения по адресу.
  * `RimMult.Server` (net10.0) — выделенный сервер (консоль, бэкапы, Docker).
  * `RimMult.Mod` (net472, Harmony, `Krafs.Rimworld.Ref 1.6.4871`) — сам мод.
  * `tests/RimMult.Tests` — тесты протокола/сервера/клиента (без RimWorld).
* `TreatWarningsAsErrors=true`, nullable включён. Неиспользуемое поле = ошибка сборки.
* **В reference-сборках RimWorld нет тел методов** — только сигнатуры. Чтобы узнать члены типа (в т. ч.
  приватные поля/методы), удобно маленьким скриптом на `System.Reflection.MetadataLoadContext` выгрузить их из
  `~/.nuget/packages/krafs.rimworld.ref/1.6.4871/ref/net472/Assembly-CSharp.dll`. Поведение методов — по памяти
  о ванильном коде/декомпиляции; не гадать там, где можно проверить сигнатуру.
* CI: `.github/workflows/build.yml` (сборка+тесты), `release.yml` («Latest build» при слиянии в main),
  `version-release.yml` (релиз по тегу `v*`).
* Мастерская Steam: `tools/workshop/publish.ps1` — сборка, тесты, упаковка и загрузка в предмет 3813029532 через
  запущенный клиент Steam (`-Check` — без загрузки). Подробности — `docs/WORKSHOP.md`.

## 4. Правила кода (как принято в репозитории)

* Комментарии и XML-доки — по-английски, коротко «что и зачем»; документация и интерфейс — по-русски
  (переводы в `mod/Languages/{Russian,English}/Keyed/RimMult.xml`, **оба файла** при каждом новом ключе).
* Сообщения коммитов — по-английски, первая строка — суть, затем список.
* Любое изменение формата пакетов → поднять `ProtocolInfo.Version` (сейчас **16**) и добавить тест на
  кодирование/декодирование. Разные версии протокола не подключаются (понятная ошибка у игрока).
* Harmony: классы патчей применяются **по одному** (`RimMultMod.PatchAll`) — ошибка одного не ломает остальные.
  Для методов, чьи имена параметров не проверены, в патчах использовать позиционные `__0`, `__1`.
  Переопределяемые методы (все `Designator.Designate*`, все `Command.ProcessInput`, `LifeStageWorker`) патчатся
  вручную по всем наследникам (`CoopOverridePatches`).
* Всё работает в главном потоке Unity, раз в кадр через `Multiplayer.Update()` (MonoBehaviour `RimMultRunner`).
* Не сохранять игру посреди тика: действия, требующие сохранения/загрузки, откладываются на следующий кадр
  (пример: `PlayerVisit.Start` → `Update`).

## 5. Как устроено (главное)

### Сеть
Хост в игре поднимает `GameServer` в своём процессе (loopback + Steam P2P + опционально UDP). Выделенный сервер —
тот же `GameServer` без игры. Пакеты — свой бинарный формат (`PacketCodec`). Кооп-трафик — `CoopMessage` с
каналом `CoopChannel`: в режиме коопа сервер пересылает гость→хост и хост→все/один; в режиме раздельных колоний —
только между двумя названными игроками (визиты, `GameServer.HandleVisit`). Позиции — ненадёжный канал, остальное —
надёжный упорядоченный.

### Кооп (папка `src/RimMult.Mod/Coop`)
* `CoopHost` — стрим: позиции 30 Гц (`PositionsFrame`, ≤900 байт, ненадёжно) + пакет состояния каждые 0.1 с
  (`CoopBatch`: исчезнувшее, новые/изменённые вещи как Scribe-XML-фрагменты, патчи `ThingPatch`, выстрелы,
  пометки, зоны, сетки, области, мир `CoopWorld`), сверка `CoopCheck` раз в секунду, смена списка карт
  `MapsChanged`.
* `CoopGuest` — приём: склейка пакетов за кадр, загрузка фрагментов (`ScribeMemory`), замена вещей, отложенная
  замена «занятых» вещей (открыто меню/окно счёта — `Busy`), позиции, сверка, перезагрузка игры при новой карте.
  `Applying=true`, пока применяется поток — патчи-перехватчики в это время не срабатывают. `CopyInPlay` — копия на
  экране (не тикать, не сохранять).
* `ScribeMemory` — сохранение/загрузка одного объекта через Scribe в памяти. Ссылки разрешаются по кешу
  «load ID → объект» (`Referenceables`): регистрируются только ID, встречающиеся во фрагменте. `replacedIds`
  исключает старые объекты, которые фрагмент заменяет. Трупы и караваны сохраняются с пешками внутри (у хоста
  эти пешки — мировые, у гостя их нет). Ссылки на битвы/боевой лог вырезаются.
* `CoopCommands` — приказы гостя, описанные так, чтобы хост нашёл то же самое у себя: дезигнатор, пункт меню по
  тексту, гизмо по типу+надписи, приоритеты, исследование, Shift (флаг `Queue`), квесты, команды модов. Гизмо,
  открывшее окно или прицел у хоста, отправляется гостю назад (`RunLocally`) и выполняется в его копии.
* `CoopTargeting` — прицельные команды: гость целится у себя, выбранная цель уходит хосту; хост жмёт ту же кнопку
  и сразу завершает прицеливание (сохраняя/восстанавливая состояние своего `Targeter`).
* `CoopEdits` — настройки, которые гость меняет в копии (счета, склады, растения, владельцы, зоны, настройки
  пешек, политики, области): сравнение с последним состоянием от хоста, изменения уходят хосту целиком.
* `CoopWorldSync` — NPC-мир коопа: отношения, исследования, письма, политики, квесты, данные модов (`ModSync`),
  глобус (`CoopGlobe`: караваны, объекты мира, приказы каравану, формирование каравана).
* `CoopVisuals` — плавное движение, летящие снаряды, прицелы, прогресс-бары у гостя.

### Раздельные колонии (папка `src/RimMult.Mod/Sync`)
* `WorldSync` (вход/выход из мира, календарь, отчёт о колониях), `TimeSync` (скорость), `RemoteColonies`
  (колонии других игроков на глобусе, меню каравана/капсул), `Parcels` + `ThingPackage` (посылки, адреса —
  `Shared/World/ParcelAddress.cs`), `PawnTransfer`, `SharedSettlements`, `DiplomacyUi`.
* `PlayerRaids` — рейды: отряд уходит посылкой `raid:`, у защитника его ведёт ИИ (`LordJob_AssaultColony`) под
  скрытой враждебной фракцией; выжившие возвращаются `raidret:` караваном.
* `PlayerVisits` — **визиты** (рейд лично и помощь союзнику): игрок сохраняет свою игру (`RimMult_VisitHome`),
  выходит из мира и загружает игру другого игрока как гость (кооп-механика между двумя игроками). Командует
  только своими пешками: их приказы уходят как сериализованные `Job` (`CoopCommandKind.Job`), у хозяина —
  белый список работ для рейдеров, всё — для помощников; между приказами `Wait_Combat`. В копии рейда стороны
  меняются местами (рейдеры → `Faction.OfPlayer`, колония защитника → враг). Конец визита → своя игра
  загружается обратно, пешки возвращаются посылкой.

### Сервер
`GameServer`: рукопожатие (протокол, пароль, баны, лимит, версия игры, хэш модов), список игроков, мир
(`WorldState` формат 5: определение планеты, колонии, время, почта, отношения, разгромленные поселения, летопись и
статистика игроков), координатор времени, дипломатия, пересылка кооп-трафика, команды (`/help` в чате).

### Летопись мира и курсоры в коопе
* **Летопись** (`GameServer.Chronicle.cs`, `Shared/World/Chronicle.cs`, окно `UI/Window_Chronicle.cs`, кнопка
  «Летопись мира» в окне мультиплеера). Сервер сам записывает то, что видит: создание мира, первый вход игрока,
  основание/оставление колоний (по разнице списков `MyColonies`), войну/мир/союзы, рейды (`raid:` → начало,
  `raidret:` → итог, мёртвые — строки `D:` в сводке), помощь, посылки, разгромленные поселения. Богатство и колонисты
  — отчёт игры раз в 30 с (`ColonyStatsReport`, сервер отсекает повторы). Всё хранится в `WorldState`, поэтому
  работает и с хостом через Steam (мир хоста лежит в его сейве), и на выделенном сервере. Не больше 1000 записей.
  Тексты — по ключам `RimMult.Chronicle.<Kind>` на языке читателя.
* **Курсоры** (`Coop/CoopCursors.cs`, канал `CoopChannel.Cursors`, ненадёжно, до 15 Гц): гость шлёт свой курсор и
  выделение хосту, хост — всё вместе гостям. Рисуются цветом игрока: крестик с именем
  (`MapInterfaceOnGUI_BeforeMainTabs`, под окнами) и рамки вокруг выделенного (`Map.MapUpdate`). Галочка в
  настройках мода. В визитах (рейд/помощь лично) не работают.

## 7. Чек-лист проверки в игре

* **Кооп, гость:** Shift-очередь; атака по цели и способность (в т. ч. псикаст Vanilla Psycasts Expanded);
  счёт на верстаке (добавить/изменить/удалить, окно счёта открыто, пока хост работает); склад; выбор растения;
  владелец кровати; расписание и политика пешки; разрешённая область; труп убитого животного (виден, с крестиком
  «запрещено»); караван: сформировать, отправить, пункт меню глобуса; хост входит на точку квеста — у гостя
  перезагрузка и новая карта; принять квест у гостя; кнопка «Загрузить заново».
* **Раздельные колонии:** война → «Отправить рейд (ведёт ИИ)» и «Напасть лично»: загрузка, управление бойцами,
  «Отступить», «Похитить», «Украсть», «Вернуться домой», конец рейда → возврат домой и караван выживших; защитник
  не видит приказов. Союз → «Помочь лично»: помощники приходят туда, где союзник; союзник не может ими
  командовать; «Вернуться домой» → люди возвращаются капсулами.
* **Моды как у хоста:** у друга другой порядок / лишний / старый мод (или старый RimMult) → «Моды» рядом с хостом в
  списке друзей (без входа) → экран различий со сборками RimMult → «Сделать всё как у хоста» → подтверждение →
  окно загрузки из Мастерской → перезапуск с модами в порядке хоста → сам подключается. Клиентские моды остались.
* **Сервер:** `/players`, `/kick`, `/ban` из чата хоста; `docker compose up -d` и `docker attach rimmult`;
  бэкапы в `server-data/backups`.
* **Курсоры (кооп):** крестик и имя друга в его цвете там, куда он навёл мышь; рамка вокруг того, что он выделил;
  у хоста видны гости, у гостей — хост и другие гости; галочка в настройках выключает.
* **Летопись:** кнопка «Летопись мира» в окне мультиплеера; события (основание колонии, война, рейд и его итог,
  посылка) появляются у всех; вкладка «Игроки» — богатство и колонисты через ~30 с после входа в мир; после
  перезапуска хоста (через Steam, из того же сейва) летопись на месте.
* При ошибках — «Отчёт об ошибке» в окне мультиплеера (файл с версиями, модами и логом).

## 8. Грабли, на которые уже наступали

* **ID в раздельных колониях не совпадают**: `Thing_Human512` у двух игроков — разные пешки. Поэтому чужую карту
  нельзя «подгрузить» в свою игру; визиты загружают чужую игру целиком.
* **Гость коопа не тикает**: всё, что в ванили считается в тике (оверлеи, сети, ИИ), у гостя не обновляется само —
  только из потока хоста.
* **Мёртвые пешки, пешки караванов** у хоста — мировые пешки; труп/караван ссылается на них по ID → у гостя
  ссылки не разрешались (труп «в сломанном состоянии» удалялся). Решено сохранением пешек внутрь.
* **Открытые меню/окна держат старый объект**: замена вещи под открытым меню ломала интерфейс → `Busy` и
  отложенная замена.
* **Steamworks на выходе из игры** бросает `InvalidOperationException` → обёрнуто.
* **Settlement.def.texture == null в 1.6** → цвета игроков: красить исходный материал, в try/catch.
* **Тайлы в 1.6 — `PlanetTile`** (слои), в протоколе передаются строкой (`ToString`/`TryParse`).
* **Краш при запуске с большой сборкой (0.5.0):** патчи на всех наследников (`Designator.Designate*`,
  `Command.ProcessInput`, `Verb.OrderForceTarget`, `JobDriver.GetReport`) ставились в конструкторе мода — Harmony
  компилирует целевые методы, это запускает статические конструкторы классов других модов, а они грузят текстуры
  не из главного потока → «Graphics device is null», краш. Теперь такие патчи помечены `[LatePatch]` и ставятся
  в `LatePatches` (`[StaticConstructorOnStartup]`, главный поток, после загрузки). Новые патчи «по всем
  наследникам» — только так. Проверено в игре на ~300 модах: краша нет.
* **Статические поля с текстурами/материалами** (`Texture2D`, `Material`) — игра при загрузке пишет «probably needs
  a StaticConstructorOnStartup attribute». Классу с таким полем ставить `[StaticConstructorOnStartup]` (сами поля
  у нас ленивые, `??=`, грузятся в главном потоке).
* **Клавиша чата** — `\` (Backslash). Y занята ванильной `Misc3` (третья кнопка у выделенного): конфликт в логе
  и двойное срабатывание. Новые клавиши проверять по `Data/*/Defs/Misc/KeyBindings` и модам владельца.
* **Мод Multiplayer (Zetrith)** несовместим (`incompatibleWith` в `About.xml` + предупреждение при запуске).
