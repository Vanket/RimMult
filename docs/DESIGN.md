# RimMult — архитектура

Мультиплеер для RimWorld 1.6: несколько колоний у разных игроков в одном мире,
кооп на одной карте, PvP, хорошая совместимость с модами и — главное — нормальный
FPS на слабых компьютерах.

## 0. Принятые решения

| Вопрос | Решение |
|---|---|
| Архитектура | **D — «владелец карты»** (у каждой карты один симулятор, остальные получают состояние) |
| Версия игры | RimWorld **1.6** (мод собирается под `net472` — так требует игра) |
| Игроков | 4–10, PvP есть |
| Время | Общее для всего мира, скорость — **голосованием** |
| Хостинг | 1) хост внутри игры через Steam; 2) выделенный сервер на **.NET 10** (Linux/Windows/Docker) |
| Steam | Обязателен: личность игрока = SteamID, раздача мода — Steam Workshop |
| Свой код или форк rwmt | **Пишем с нуля.** Ядро rwmt — lockstep (вариант A), его не переделать в D. Идеи (API синхронизации для модов, подход к патчам) изучаем, но код не копируем — так нет проблем с лицензией и архитектурой |

## 1. Почему у друга было 20 FPS и как мы это лечим

В lockstep-мультиплеере (rwmt) **каждый компьютер симулирует все карты всех игроков**.
Две колонии — значит, слабый ПК друга считает и свою колонию, и твою, да ещё должен
не отставать от тебя. Отсюда 20 FPS на скорости 2.

В RimMult:

1. **Каждый компьютер симулирует только свои карты.** Чужие колонии не тикают у тебя
   вообще — ноль нагрузки. Чтобы показать чужую колонию на глобусе, хватит пары байт.
2. **В гостях — «кукольный» режим.** Когда ты приходишь на чужую карту, твой клиент её
   *не симулирует*: он получает от владельца поток изменений и только рисует
   (интерполяция позиций пешек, анимации). Это в разы дешевле симуляции.
3. **Перенос симуляции на сильный ПК (offload).** Если клиент не тянет свою карту на
   выбранной скорости, сервер это видит (каждый владелец сообщает свой реальный TPS) и
   предлагает: «Передать симуляцию колонии X игроку Y?». После переноса друг играет
   своей колонией как гость: управляет, видит всё, но считает её твой мощный ПК.
   Для него это та же картинка, что и в гостях, — FPS высокий.
4. **Сеть и разбор пакетов — в отдельном потоке.** Применение изменений к миру
   ограничено бюджетом на кадр, чтобы входящий трафик не давал рывков FPS.
5. **Interest management.** Данные карты получают только те, кто на неё смотрит прямо
   сейчас. Твоя колония не отправляет ничего другу, пока он не открыл её.

## 2. Общая схема

```
                 ┌────────────────────────────────────────┐
                 │        Сервер (ServerCore)             │
                 │  • лобби, SteamID, проверка модлиста   │
                 │  • координатор времени + голосование   │
                 │  • кто чем владеет (карты, мир)        │
                 │  • раздача диапазонов ID               │
                 │  • ретрансляция, чат, бэкапы           │
                 └───────▲───────────────▲───────────────▲┘
                         │               │               │
          ┌──────────────┴──┐   ┌────────┴────────┐   ┌──┴──────────────┐
          │ Клиент A (мощный)│   │ Клиент B (слабый)│   │ Клиент C        │
          │ симулирует:      │   │ симулирует:      │   │ симулирует:     │
          │  • мир (глобус)  │   │  • (ничего —     │   │  • карту C      │
          │  • карту A       │   │   карта B        │   │                 │
          │  • карту B       │◄──┤   перенесена     │   │ смотрит карту A │
          │   (offload)      │   │   на A)          │   │ в гостях        │
          └──────────────────┘   └──────────────────┘   └─────────────────┘
```

`ServerCore` — библиотека под `netstandard2.0`. Она запускается в двух местах:

* **внутри игры** у хоста (транспорт — Steam Networking Sockets, NAT пробивает Steam,
  порты открывать не нужно);
* в **выделенном сервере** `RimMult.Server` на .NET 10 (транспорт — UDP через LiteNetLib).

> ⚠️ Выделенный сервер **не может сам симулировать RimWorld**: код игры завязан на
> Unity. Поэтому симуляцию всегда выполняют клиенты. Сервер решает, *кто* что
> симулирует, и хранит мир, пока все оффлайн.

### Авторитеты

| Объект | Кто симулирует |
|---|---|
| Карта колонии | её владелец (или тот, кому её перенесли) |
| Временная карта (место события, поселение для рейда, сайт квеста) | тот, кто её создал (обычно владелец каравана); в PvP — защищающийся или нейтральный арбитр |
| Мир: глобус, фракции, караваны в пути, квесты, мировые пешки | «владелец мира» — назначается сервером, по умолчанию самый мощный клиент |

## 3. Время

У мира есть **разрешённый тик** (horizon), им управляет сервер.

1. Каждый авторитет сообщает: «я на тике N, могу держать K тиков/сек».
2. Сервер вычисляет целевую скорость по голосам (см. ниже) и разрешает всем двигаться
   до `min(тики авторитетов) + допуск`. Допуск — 1,5 реальной секунды на текущей скорости
   (90 тиков на скорости 1, 540 на скорости 3), но не меньше 60 тиков. Фиксированный допуск
   в тиках на высокой скорости короче задержки сети, и колонии начинают дёргаться.
3. Быстрые машины упираются в этот предел и ждут — время в мире остаётся общим.
   Медленная машина тормозит всех, поэтому сервер подсвечивает «узкое место» и
   предлагает offload (п. 1.3).

**Голосование за скорость** (режим задаётся в настройках сервера):

* `Lowest` — идёт самая низкая скорость из голосов (по умолчанию: никто не страдает);
* `Majority` — большинство, при равенстве — меньшая;
* `Host` — решает хост/админ.

**Пауза:** по умолчанию любой может поставить паузу (как в обычной игре — случилось
что-то важное) и любой может её снять: выбор скорости во время паузы снимает чужие
голоса за паузу.

Скорости RimWorld: ×1 = 60 тиков/с, ×2 = 180, ×3 = 360, ×4 (ultrafast, dev) = 900.

**Межкартовые события** (караван дошёл, торговля, рейд) получают метку мирового тика
и применяются, когда обе стороны дошли до этого тика. Допуск в 60 тиков — это 1 игровая
секунда, на глаз незаметно.

### Как это сделано сейчас (этап 2)

* **Одна планета у всех без передачи планеты.** Генерация мира в RimWorld детерминирована:
  одинаковые сид, параметры и моды дают одинаковую планету. Сервер хранит только
  `WorldDefinition` (сид, покрытие, осадки, температура, население, ориентиры,
  загрязнение, список фракций). Кто создаёт колонию в существующем мире, проходит
  обычное «Новая колония», но страница параметров мира заблокирована на значения сервера.
* **Кто задаёт мир:** первый игрок, создавший колонию (или хост, запустивший сервер из
  уже загруженной игры, или игрок, нажавший «Сделать мир общим»).
* **Каждая колония — обычная одиночная игра** своего игрока, где он и есть «фракция
  игрока». Чужие колонии видны на глобусе как объекты `RimMult_RemoteColony` (в сейв не
  пишутся, собираются из списка сервера). Основать колонию ближе 4 клеток к чужой нельзя.
* **Общее время = общий календарь (`TicksAbs`).** При входе в мир сервер присылает
  текущее время мира, и календарь колонии сдвигается (`gameStartAbsTick`). Колония,
  которая была оффлайн, просто «заморожена» и продолжает с общей даты.
* **Скорость:** кнопки скорости, хоткеи и пробел становятся голосом. Игра идёт с
  итоговой скоростью сервера и не уходит дальше горизонта. В полоске сверху видно
  ваш голос и кого ждём.
* **Чтобы один игрок не останавливал всех:** автопауза игры на событиях отключена,
  окна (торговля, диалоги) не ставят игру на паузу — как в других мультиплеер-модах.
* Сервер хранит мир: выделенный — в `world.dat`, хост в игре — внутри своего сейва.

**Ограничение этапа 2:** NPC-фракции, квесты, торговцы и события пока у каждого игрока
свои (локальные). Общий «владелец мира» для них — дальше по плану.

## 4. Репликация (как гость видит чужую карту)

1. **Снимок.** При входе на карту владелец сериализует её *тем же механизмом, что и
   сохранение игры* (`Scribe`/`ExposeData`), сжимает LZ4 и отправляет.
   Главная идея для совместимости: **любой мод уже умеет сохраняться**, значит его данные
   доезжают до гостя без отдельных патчей.
2. **Быстрый канал** (каждые несколько тиков): видимое состояние пешек и движущихся
   объектов — позиция, путь, поворот, текущая работа, стойка/выстрел, изменения
   здоровья. Здесь стоят ручные патчи Harmony, это немного объектов.
3. **Медленный канал / «ротационная сверка».** Каждый тик владелец пересериализует
   несколько объектов (по кругу + те, что помечены «грязными»), сравнивает хэш с
   отправленным ранее и при отличии отправляет объект целиком. Так любое состояние
   мода, которое мы не отслеживаем явно, всё равно сходится за секунды.
4. **Спавн/деспавн** объектов — отдельные события с сериализованным объектом.

Гость **не тикает** карту. Окна осмотра, вкладки здоровья и т. п. читают
реплицированные объекты, поэтому выглядят как обычно.

### Команды

Всё, что игрок делает на карте, которую не симулирует сам (приказы пешкам, зоны,
чертежи, кнопки модов), перехватывается и уходит владельцу карты как команда.
Владелец выполняет её у себя, а результат приходит обратно через репликацию.
Задержка = пинг до владельца; для RimWorld это незаметно.

Перехват делается **генерически**, патчами на базовые точки входа:
`Command.ProcessInput`, `FloatMenuOption.Chosen`, `Designator.DesignateSingleCell/Thing`,
`Gizmo`-кнопки, изменения настроек работ, расписаний, политик. Поэтому кнопки
большинства модов работают «из коробки».

### Как это сделано сейчас (этап 4: кооп на одной карте)

Хост выбирает режим в окне «Хост»: **раздельные колонии** (этапы 2–3) или **кооп на одной карте**
(`GameMode` в `ServerWelcome`). В коопе симулирует только игра хоста, гости играют её копию.

1. **Вход.** Гость жмёт «Войти в колонию хоста» → `CoopMessage(JoinRequest)`. Сервер ставит мир на
   «удержание» (`TimeCoordinator.SetHold`: пауза, которую нельзя снять голосованием). Хост сохраняет игру
   обычным `GameDataSaveLoader.SaveGame`, сжимает gzip и отправляет этому гостю. Гость загружает её как
   обычное сохранение, шлёт `Ready` — удержание снимается, время идёт дальше.
2. **Поток состояния.** Два канала:
   * **Позиции** (`PositionsFrame`) — ~30 раз в секунду, по *ненадёжному* каналу, кадрами до 900 байт:
     потерянный кадр заменяет следующий, и тяжёлые данные никогда не стоят в очереди перед ними.
   * **Состояние** (`CoopBatch`, каждые 0.1 с, только если что-то изменилось): исчезнувшие объекты; новые объекты
     целиком (XML через `Scribe`); **патчи на месте** (`ThingPatch`: прочность, размер стопки, рост растений,
     прогресс стройки, «запрещено») — вместо перезагрузки объекта; полные копии пешек, у которых изменился вид
     (несёт предмет, призвана, упала, сменила одежду/оружие), и раз в 0.5 с ещё одна пешка по кругу — для
     потребностей и здоровья; редкая полная сверка XML остальных предметов (топливо, энергия, данные модов).
     Полных копий не больше 12 за пакет. Пометки — сразу при изменении (дешёвый хэш каждый пакет), зоны — до
     0.25 с, сетки пола/крыш/тумана — раз в секунду.
   * **Позиции** несут и точку, где хост рисует пешку (между клетками на ходу); гость плавно ведёт пешку к ней
     (свой `DrawPos`), поэтому нет телепортов от клетки к клетке. **Выстрелы** (`CoopShot`) — отдельные события:
     гость рисует летящий снаряд и проигрывает звук оружия, сам снаряд не симулируется. Что хост нажал
     (кнопки на выделенном) и что сделал по приказу гостя, уходит гостям сразу целиком.
3. **У гостя** копия не тикает (`TickManager.DoSingleTick` пропускается), но часы «идут» на общей
   скорости, поэтому пешки плавно доезжают до присланных клеток. Все пакеты, пришедшие за кадр,
   **склеиваются** и применяются один раз (слабый ПК догоняет, а не отстаёт всё больше — так копилась
   прежняя задержка ~10 с). Полная копия заменяет объект с тем же ID; ссылки разрешаются через кеш
   «ID → объект», регистрируются только ID, упомянутые во фрагменте (раньше на каждый пакет перебирался весь мир).
4. **Приказы гостя** (`CoopCommand`) перехватываются патчами и выполняются у хоста:
   дезигнаторы (все наследники `Designator`, включая моды; стройка, зоны, установка), пункты меню
   правой кнопки (по тексту пункта), гизмо-кнопки (по типу и надписи — призыв, запрет и т. д.),
   приоритеты работ, исследование. Окна, которые приказ открыл бы у хоста, сразу закрываются.

Ограничения первой версии: не синхронизируются области (дом, разрешённые зоны), счета
(bills), настройки складов и политики, расписания, письма и глобус (караваны гостю не видны);
команды с выбором цели (`Command_Target`: атака по цели, способности) у гостя отклонены — для
призванных пешек работают приказы правой кнопкой; гизмо, открывающие своё окно/меню (например,
выбор растения), у гостя не срабатывают; карта, созданная хостом после входа гостя, видна после
перезахода; сохраняет игру только хост. Выделенный сервер всегда работает в режиме раздельных колоний.

## 5. Перенос объектов между картами и уникальные ID

Караваны, транспортные капсулы, обмен в торговле: отправитель сериализует пешек и
предметы через `Scribe` и шлёт получателю. Тот загружает их у себя, как при загрузке сейва.

**Проблема:** RimWorld выдаёт ID (`thingIDNumber`, `UniqueIDsManager`) последовательно
в рамках одной игры. Если симуляторов несколько, ID будут совпадать.
**Решение:** сервер выдаёт каждому авторитету **диапазоны ID в аренду** (блоки по
100 000), патч на `UniqueIDsManager` берёт ID из своего блока. Ссылки на мировые
объекты (фракции, идеологии, мировые пешки) идут по `loadID` и разрешаются через
владельца мира.

### Посылки (этап 3, первая часть)

* Транспортные капсулы можно запустить в колонию другого игрока (цель — его колония на
  глобусе), караван может дойти до неё и «передать груз».
* Предметы упаковываются системой сохранений игры (`Scribe`, gzip), поэтому любые
  предметы из любых модов доезжают целиком. У получателя им выдаются новые ID — каждая
  игра нумерует свои вещи сама, аренда ID для этого не нужна.
* Сервер хранит посылку, пока получатель не подтвердит, что она приземлилась (почта для
  оффлайн-игроков, переживает рестарт сервера). Если колонии получателя больше нет,
  посылка возвращается отправителю. Посылки, упакованные без связи, ждут в сейве.
* Колонисты и животные колонии тоже могут переселяться (капсулами или караваном —
  «присоединиться к колонии»). Пешка полна ссылок на свою игру (отношения, воспоминания о
  других пешках, кровати, зоны, политики, идеология, фракция): перед отправкой они
  обрезаются, а по прибытии направляются на новую колонию (её фракция, основная идеология,
  политики по умолчанию). Нельзя: механоидов, пешек с имперским титулом, механиторов с
  механоидами, пленных и рабов, трупы.

### Обмен между игроками

* «Предложить обмен» на колонии игрока. Каждый выбирает, что отдаёт со своих складов,
  видит предложение другого и его стоимость.
* Каждое предложение имеет версию; «Принять» — согласие с предложением конкретной версии;
  затем каждая сторона шлёт подтверждение пары версий (мои, твои). Обмен совершается,
  только когда оба подтверждения совпали — изменение в последний момент аннулирует всё,
  и никто не отдаёт товар в одиночку. После подтверждения отменить нельзя.
* Товары каждой стороны уходят посылкой и прилетают капсулами.
* **Торговля караваном:** караван, дошедший до колонии игрока, торгует своим грузом и
  животными. Купленное грузится прямо в караван (адрес посылки `caravan:<id>|<колония>`;
  если караван уже исчез — к колонии), проданное спускается капсулой у колонии продавца.
  Проданное вьючное животное оставляет свой груз остальным, как в обычной торговле.
* Сервер лишь пересылает сообщения между игроками в мире (`PlayerRelay`).

### Цвета игроков и общие поселения NPC

* Сервер выдаёт каждому игроку цвет из палитры (первый — зелёный) и помнит его. Колонии
  на глобусе (и своя, и чужие), имена в лобби и чате — в цвете игрока.
* Поселение NPC, уничтоженное одним игроком, исчезает у всех. Отношения с фракциями,
  квесты и торговцы остаются у каждой колонии своими.
* Большие сообщения по Steam режутся на части (лимит Steam — 1 МБ на пакет).

## 6. Колонии, дипломатия, PvP

* Каждый игрок — своя фракция (своё имя, цвет, идеология). Можно иметь несколько колоний.
* Отношения между игроками: союз / нейтралитет / война. Меняются по взаимному согласию
  (союз) или в одностороннем порядке (война), с кулдауном.
* Торговля: караваном или удалённо (торговая консоль ↔ консоль), общий рынок.
* **Визиты:** прийти караваном к союзнику и играть на его карте (кооп).
* **PvP-рейд:** атакующий отправляет своих пешек. Карту симулирует защищающийся,
  атакующий управляет своими пешками командами (как гость). Опция сервера: симулирует
  нейтральный арбитр (третий игрок или выделенный «доверенный» клиент) — против читов и
  чтобы слабый ПК защитника не был узким местом.
* Опции сервера: защита новичков (N дней без PvP), лимиты рейдов, «оффлайн-рейды» запрещены.

### Как это сделано сейчас (этап 5)

* **Отношения** — нейтралитет / союз / война между парами игроков (по SteamID). Хранятся на
  сервере в `WorldState` (формат 4) и рассылаются в `WorldUpdate`. Правила в `DiplomacyBook`:
  войну объявляет одна сторона (только если сервер разрешает PvP — `AllowPvp`, галочка у хоста);
  мир и союз — предложение + согласие второй стороны (`DiplomacyRequest` → `DiplomacyNotice`);
  союз можно разорвать в одностороннем порядке, войну союзнику объявить нельзя, пока союз не
  разорван. Войну, мир и союзы видят все, предложение — только адресат.
* **Кнопка «Дипломатия»** на колонии другого игрока; отношения видны в подсказке колонии и
  в списке игроков лобби. С врагом нельзя торговать.
* **Рейд.** Караван у вражеской колонии → «Напасть на колонию …», или капсулы → «Десант в
  капсулах на …». Отряд (колонисты и животные, со всем, что несут) упаковывается как посылка
  с адресом `raid:<id>|<c|p>|<клетка>`. Сервер пропускает её, только если игроки воюют и
  защитник сейчас в мире; иначе отряд возвращается домой капсулами.
* **У защитника** игра сама ведёт бой: рейдеры входят с края карты или падают в капсулах и
  получают обычный ИИ рейда (`LordJob_AssaultColony`: штурм, кража, похищение, бегство) от
  скрытой враждебной фракции. Кто уходит с карты живым, перехватывается (`Pawn.ExitMap`) и
  ждёт конца рейда вместе с тем, что несёт. Рейд окончен, когда на карте не осталось рейдеров,
  способных сражаться.
* **Итоги.** Выжившие, похищенные колонисты защитника и украденное уходят атакующему
  (`raidret:`): у него они появляются караваном у атакованной колонии; похищенные — его
  пленники. Убитые и раненые остаются у защитника (трупы и снаряжение — его добыча, раненых
  можно взять в плен). Оба получают письма с итогами. Если атакующий не в сети, отряд дождётся
  его в почтовом ящике сервера.

Пока нет: управления своими рейдерами во время боя (атакующий не видит бой — для этого нужен
быстрый канал кооп-режима), защиты новичков и лимитов рейдов, помощи союзников.

### Игрок вышел из игры

Настройка сервера: колония **замораживается** (стазис, время для неё не идёт, к ней нельзя
прийти рейдом) или **передаётся на симуляцию** другому клиенту (продолжает жить).

## 7. Совместимость с модами

1. **Модлист.** При входе сравниваются список модов, их порядок, версии (хэши сборок) и
   конфиги. Клиенту показывается разница, моды из Workshop подписываются одной кнопкой
   (Steam UGC API). Есть серверный список «только клиентские моды» (UI, текстуры, звук),
   которые могут отличаться.
2. **Данные** — через `ExposeData` (см. п. 4), без патчей.
3. **Команды** — генерический перехват (п. 4).
4. **API для авторов модов** — `RimMult.API` (отдельная маленькая сборка, мягкая
   зависимость): `[SyncCommand]`, `[ReplicateField]`, `IsHost/IsPuppet`, хуки «объект
   пришёл с другой карты».
5. **Пакет совместимости** для популярных модов: Combat Extended, Vanilla Expanded,
   HAR, Dubs Bad Hygiene, Performance Fish и т. д.
6. **Отладка расхождений:** команда «сравнить объект/карту с владельцем» → отчёт, какие
   поля и какого мода различаются.

Ключевое отличие от lockstep: нам **не нужен детерминизм**. `Random`, порядок словарей и
float в модах ничего не ломают. В худшем случае картинка у гостя на долю секунды неточна,
а ротационная сверка это исправит.

## 8. Сеть и протокол

* Сервер слушает сразу несколько «точек входа» через `TransportHub`: Steam P2P
  (друзья), UDP/LiteNetLib (вход по адресу, выделенный сервер) и loopback (сам хост
  играет через свой сервер теми же пакетами, что и все).
* Steam P2P не знает про соединения, поэтому поверх него свой маленький фрейминг
  (`P2PFrame`): connect/accept/disconnect, heartbeat раз в 2 с, таймаут 20 с,
  номера последовательности для ненадёжных пакетов.
* Хост объявляет себя через Steam rich presence (`connect`), поэтому в списке друзей Steam
  работает «Присоединиться к игре», а в игре виден список друзей, создавших игру.
* Причина кика передаётся как «прощальный» пакет (в UDP — прямо внутри пакета
  отключения), поэтому она не теряется. При несовпадении модов в кике лежит список
  модов сервера, и клиент показывает точную разницу: каких модов нет, какие лишние,
  где другая версия, отличается ли порядок.
* Каналы: надёжный упорядоченный (команды, события) и ненадёжный последовательный
  (быстрый канал позиций).
* Пакет: `[тип: ushort][тело]`. Сериализация — свой компактный бинарный формат
  (`ByteWriter`/`ByteReader`, varint). Снимки — XML Scribe + LZ4.
* Большие снимки режутся на фрагменты и передаются с ограничением скорости, чтобы не
  забивать канал.
* Версия протокола проверяется при рукопожатии.

### Аутентификация

Клиент передаёт SteamID и тикет `GetAuthSessionTicket`.
**Открытый вопрос — проверить в прототипе:** как выделенный сервер без ключа
издателя проверит тикет. Варианты: Steamworks GameServer API на сервере; запасной
вариант — доверять SteamID + пароль сервера/вайтлист.

## 9. Дистрибуция

* **Мод** → Steam Workshop (зависимость: Harmony).
* **Выделенный сервер** → GitHub Releases (self-contained бинарники Linux/Windows) и
  Docker-образ. Конфиг — `server.json`, админ-консоль, автобэкапы мира.
* Отдельное приложение в Steam потребовало бы своего AppID (Steam Direct), поэтому
  сервер распространяем вне Steam, а мод — через Workshop.

## 10. Структура репозитория

```
src/RimMult.Shared/     netstandard2.0  протокол, пакеты, сериализация, логика времени, P2P-фрейминг

src/RimMult.ClientCore/ netstandard2.0  клиентская сессия (вход, игроки, чат, время) — тестируется без игры
src/RimMult.Net.LiteNet/netstandard2.0  UDP-транспорт (выделенный сервер и вход по адресу)
src/RimMult.Server/     net10.0         выделенный сервер (консоль/Docker)
src/RimMult.Mod/        net472          мод RimWorld (Harmony-патчи, UI, клиент)
mod/                                    папка мода для игры (About, 1.6/Assemblies)
tests/                  net10.0         юнит-тесты Shared/ServerCore
docs/                                   документация
```
